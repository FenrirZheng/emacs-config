Scope:
- Benchmark repo: 1120 Go files, 232k lines. One server, gopls v0.22.0, on Emacs 30.1.
- Rule fixed before the run: L win needs at least 25% and at least 5 ms below off in all three rotations. Off blocked about 1.3 ms in total on this reply, so the 5 ms floor could not be met at this payload size. Larger replies were not measured.
- Batch has no redisplay, so the verdict covers process-side blocking, not perceived latency.
- gopls's =completionBudget= was ="0s"= in all three modes, set in the benchmark child only (live default: 100ms), so completion replies can differ from live ones.
- The harness's target picking and connect call are Go-only. A rust-analyzer run is deferred and needs harness work first.
- Hover and =hover-small= counts are in bytes, because in bytecode mode the same text has a different character =length=.

Found on the way: in bytecode mode, non-ASCII text reaches Lisp undecoded, so hover, completion, diagnostics, symbol names and =newText= hold raw bytes when rendered or inserted. Measured in batch on 2026-11-06, not observed in the live daemon. =io-only= was not affected. Scope, mechanism and what was not tested: "eglot-booster-bytecode-unibyte" in =_doc/GOTCHAS.md=.
